## [0.0.1] - 2026-10-23

First public build, an early preview for macOS 12+ on Apple silicon. Not notarized yet. Highlights:

- **⌘P everywhere:** pull requests, work items, runs, people and commands from a local index, with filters like `author:@me`, `state:`, `updated:<7d`.
- **Pull request review:** side-by-side diffs computed locally, inline threads, viewed files, votes, comments and status changes without opening the browser.
- **Inbox and smart nudges:** one row per item instead of an email per event, priorities, snooze, mute, quiet hours; nudges for reviews waiting, failing builds and stale PRs.
- **Work items:** detail view with in-place editing of state, assignee, area, iteration, description, links and comments, guarded against conflicting edits.
- **Today, pins and activity:** your day at a glance, up to 20 pinned items, and a live log of every request adoken sends.
- **33 built-in theme variants, custom backgrounds, optional sounds** and the opt-in Ken arcade layer, all respecting Reduce Motion.
- **Local-first:** one SQLite store per org, a PAT in the Keychain only, no adoken server between you and Azure DevOps. Try it on a fictional org with `ADOKEN_DEMO=1`.

- ⌘P searches the local store (spec 0003): pull requests, work items, pipeline runs, people, repositories, projects, and commands. Scopes `!` `#` `@` `>` `p:` `r:` `proj:`, filters (`author:@me`, `reviewer:`, `vote:`, `is:`, `repo:`, `branch:`, `type:`, `state:`, `assigned:`, `priority:`, `area:`, `tag:`, `status:`, `project:`, `updated:<7d`, negation with `-`), direct jumps (`!912`, `#1234`, bare ids, pasted `dev.azure.com` / `visualstudio.com` links), "did you mean" for unknown filters (Tab fixes), and result rows customizable per type in `settings.toml` `[palette.rows.<type>]`. - Local store (ADR 0001): one SQLite file per org in WAL mode with one writer and a pool of read-only connections, forward-only migrations with a pre-upgrade backup, refusal to open a newer schema, idempotent upserts guarded by revision and update time, a search corpus kept in step with every write (⌘P titles and full-text search over descriptions and comments), and versioned tables for other features' local state.
- Sync engine (spec 0002): hot, warm and cold passes over pull requests, threads, work items and pipeline runs, read-only (GET, plus WIQL queries). Each page commits together with its cursor, so an interrupted sync resumes where it stopped. Every request goes through a rate governor: at most 4 at a time, `Retry-After` honored, hot tier only at ≤ 20% of the rate limit, 30 s → 5 min backoff on TF400733, and a budget of 300 requests per 5 minutes. The first sync is silent. After that, changes become deduplicated events (review requested, comments, mentions, votes, pushes, status, merge conflicts, work item assigned or changed, build completed), and your own actions are marked as such.

- Pull request files on a real organization (spec 0004 FR-1–FR-3): opening a PR fetches its latest iteration's changed files against the merge base (every page, so PRs with more than 100 files are complete) and each file's base and target contents, and computes the diff locally. - Back and forward (spec 0018): ⌘[ / ⌘], the mouse's back and forward buttons and swipes, the titlebar's ‹ › (their tooltips name the place, "Back to Inbox · Unread · Pull requests") and ⌘P › "Go back" / "Go forward" move through one history per window (the last 50 places, kept in memory). Opening something from a list, ⌘P, a link, a pin, Today or the Activity drawer adds a place; moving inside a view (`j`, `t`, ⌘⇧D) doesn't. A restore still waiting for data gives way to any key or click and gives up after 5 s. Going back and forward sends no requests, and the keys don't fire while you type. In a review, Esc goes up to the pull request list and counts as a back when you came from it.
- One token, and Settings › Account (spec 0001 and 0009 amendments, user decision 2026-10-01): adoken asks for one token with every permission its features use, so no feature asks you to renew. Settings › Account shows where the token came from (Azure CLI or pasted), when it was created and when it expires, each permission as Granted, Not checked yet or Missing (a refused write marks it missing, an accepted one proves it), Change access… (Review or Read-only) and Sign out. Replace token… (also in ⌘P) creates a token with the current permission set — through the Azure CLI, or a two-step sheet when there is none — swaps it in, verifies it and revokes the old one; sync resumes and newly granted features turn on without a restart. Tokens created through the Azure CLI are replaced quietly in the week before they expire (at most once a day, never with a sign-in prompt), followed by one quiet inbox item ("adoken replaced its Azure DevOps token · the new one expires …", no banner or sound) and "Replaced automatically on …" in Account; if that still fails 2 days before expiry, one quiet item offers Replace token…. A rejected or expired token raises one quiet inbox item per episode, and the Activity drawer's Sync tab offers Replace token…. The expiry reminder (and its `notify.token_expiring` sound) and every "Renew token" prompt are gone; a missing permission is explained with a passive hint. Onboarding opens on a new illustrated Welcome screen, lists every permission with its `vso.*` id and what it allows, keeps Read-only as a link under that list, offers token lifetimes of 30, 90 or 180 days or 1 year, and records an "Expires on" date for a pasted token.
- Work items: area and iteration dropdown (spec 0008 amendment): on By area and By iteration the path is a button; a click, `/`, or ⌘P › "Work items: Filter by area…" / "Filter by iteration…" from any view opens a tree of every area or iteration in your projects, one root per project, with the open items at or below each node; type to narrow. Choosing a node with children lists it and everything below ("Payments and below"), selects the first item and gives the list the keyboard; Esc changes nothing, and the choice lasts the session. Iterations offer Current / Next / Recent per project. A tree older than a day is read once when you open the dropdown, at user priority, and merges in place without moving your query or highlight; offline and the demo org send nothing. `[` `]` still step through the busiest paths.
- Celebrations (spec 0022, design `docs/design/ken.md` §12): when Azure DevOps confirms that you moved a work item into review or done, or that a pull request you completed in adoken merged, a short confetti puff (into review) or two-wave burst (done, merged) plays from the state chip on that same frame — about 0.65 s and 1.5 s, never blocking keys. Changes seen only through sync, and moves backward, never celebrate. Ken's arcade mode adds an original 済 seal stamp and sparks; under Reduce Motion, or when several land at once, a static sparkles glyph shows (plus a toast for done and merged). Each plays one new sound, `ui.celebrate_step` or `ui.celebrate_milestone`, that follows quiet hours. Settings › General › Celebrations turns them off, separately for pull requests and work item states, and shows which states celebrate (`[celebrations]` in `settings.toml`); ⌘P has "Preview celebration". While idle they draw and allocate nothing. Quiet mode (⌘P "Quiet mode: turn on or off", "Quiet mode for 1 hour") works with Ken off, shows in the statusbar, and hides celebrations, Ken and sounds.
- Guided tours (spec 0020): the first time you open Today, Inbox, a pull request review, a work item or ⌘P, a short tour of 3–5 coach marks points at the parts of the view and their keys, read from your live keymap so rebound keys show correctly. It waits for 1 s without input and no overlay open, and starts at most one tour every 3 minutes; ←/→, ↩/Space and Tab drive it, Esc skips it, and any other key ends it and does what it always does. Screen readers hear each step. Replay any tour from ⌘P ("Tour: Today", "Tour: Inbox", "Tour: Pull request review", "Tour: Work item", "Tour: Command palette", "Tour: This view"). Settings › General › "Show tours the first time you open a view" turns first-use tours off, and "Show tours again" resets them (`[tours]` in `settings.toml`).
- Global shortcut (spec 0021, macOS): Hyper+A (⌃⌥⇧⌘A) in any app brings adoken to the front — unhidden, unminimized, or with its main window reopened. Settings › Keyboard › Global shortcut records another chord (Esc cancels, ⌫ clears; a chord that would clash, such as ⌘P, is refused with the reason), clears it or resets it. Keys follow your keyboard layout, edits to `settings.toml [hotkey] summon` apply within seconds, and if another app holds the chord adoken says so once. ⌘P › "Global shortcut settings…"; the chord is in the cheat sheet.
- Resource meter (spec 0023, off by default): Settings › General › "Show memory and CPU in the statusbar" or ⌘P › "Statusbar: Show or hide memory and CPU" shows adoken's own memory (as Activity Monitor counts it) and CPU in the statusbar ("260 MB · 3% CPU"). It samples off the UI thread every 2 s while adoken is in front and every 10 s behind it, stops while hidden or off, changes its text at most every 5 s and only for a real change, and drops CPU first when the statusbar is narrow. Its menu has Copy resource usage (a one-line report for bug reports with no org or item data, also in ⌘P) and Hide from statusbar. Saved as `[activity] resource_meter`.

### Fixed
- Work items from any process template: Product Backlog Items (Scrum), Requirements (CMMI) and custom types were dropped by sync, because only six stock types were recognized. Every type is now kept under its Azure DevOps name, and open vs. closed comes from the state categories Azure DevOps returns for each type (fetched once a day), so custom states such as "Shipped" count as done.
- The request log (`ADOKEN_SYNC_LOG` and the in-memory ledger) recorded two things its "ids replaced" promise excludes: the git object id of each downloaded pull request file (`…/blobs/{sha}`), and the project's name when a pinned work item's project wasn't selected (`_apis/projects/{project}`). Both are now templated.
- Jumping between pull requests while a comment composer is focused now flushes the unsent draft before navigation drops the editor, rather than losing text inside the autosave debounce.
- Icons without an explicit color now use the inherited text color; Unpin and disclosure glyphs were otherwise invisible in the current GPUI renderer. The Unpin hover control keeps a stable layout, avoiding GPUI's “must call prepaint before paint” panic.
- The vote menu opened by clicking Vote… could not be dismissed (spec 0004 FR-18): a click outside it moved focus to the review, whose key context while a menu is open binds no `Esc`, so the menu stayed open and every review key was dead. Every overlay (vote and status menus, Complete sheet, confirmations, work item picker) now closes on a click outside and on `Esc`, and hands the keyboard back to the review.
- Pull requests that delete files showed "Couldn't load the file list … invalid type: null, expected a string": Azure DevOps sends deleted files with `item.path: null` and the path in `originalPath`. Deletes now read their path from there, and an entry that names no file is skipped instead of failing the whole list.
- Sync against a real org: `connectionData` is requested with its preview API version (it failed every pass before), title-index rows from the reporting feed are no longer dropped (its identities are strings), deleted work items are recognized, work item descriptions are stored as plain text instead of HTML, your open work items older than 30 days are synced, and the title index covers all work items rather than the last 12 months (spec 0002 Q-2).
- The local store for a connected org lived at the data folder root instead of `orgs/<org>/`; an existing file is moved there on first launch.
- Text inputs no longer paint past their border: text longer than the box scrolls horizontally to keep the caret (and IME composition) in view, and clicks/drags map through the scroll. The PR review composer card shrinks with a narrow diff pane, and its "Esc closes" hint moves to its own line instead of being cut off.
- Opening a pull request whose files weren't downloaded yet was slow while sync was busy (user decision 2026-09-30): the rate governor served requests first come, first served, so the PR's file list and file contents waited behind queued sync requests (694 ms to the first file at 80 ms latency in our measurement, 261 ms now). Requests are now admitted by priority (yours, then hot, warm, cold; spec 0002 FR-7), sync can use at most 3 of the 4 connections so one is always free for you, and a sync request passed over 8 times goes next so sync never starves. The selected file now downloads before the prefetched ones instead of racing them.
- Pull request review loading states (spec 0004, user decision 2026-09-30): a PR opened before its file list was synced shows placeholder rows in the file tree and "Loading files…" in its header instead of an empty tree; if the download fails, the tree says why with Retry (⇧L, also ⌘P › "Retry loading files"). A file still downloading shows a spinner with its name, and after 3 s what it's waiting for ("Downloading 2 files from Azure DevOps…", "Waiting for Azure DevOps (sync in progress)…", slowed down by Azure DevOps, or offline). Nothing shows for loads under 150 ms, and the spinner holds still with Reduce Motion. ⇧L also retries a file whose download failed.
- Pull requests list: ↑↓ didn't move the selection after clicking a row (user decision 2026-09-30). The click opened the review beside the list and gave it the keyboard, so the arrows moved the diff cursor instead; with the list hidden (⌘⇧↩) its keys went nowhere. The list now has the keyboard whenever it's shown: on entering the view, after going back, and after a click on the list.
- Scrolling the theme grid or code font list in Settings › Appearance (also About's third-party licenses and onboarding's organization and project lists) scrolled the whole page along with it; the wheel now stays inside the list under the pointer.
- After a confirmed work item edit, the detail's state chip went back to the old state for about 400 ms until the next store reload; it now shows Azure DevOps' answer at once.
- Policy group avatars showed "[" instead of the group's initials ("RP" for "[Contoso]\React PR reviewers").

### Changed
- Feature diet (spec 0025): section keys follow the sidebar: ⌘1 Today, ⌘2 Inbox, ⌘3 Pull requests, **⌘4 Work items** (was Search), ⌘5 Pipelines, ⌘6 Search. The ⌘/ cheat sheet groups shortcuts by screen. Calm mode, sound mute and the celebration on/off commands are now one **Quiet mode** (⌘P "Quiet mode: turn on or off", "Quiet mode for 1 hour"): no sounds, celebrations, Ken HUD, K.O. or Ken toasts while it is on. Paired ⌘P commands became single toggles (first-use tours, memory and CPU, Ken streak pause, "Sync: Pause or resume", threads/files). Settings › Sounds is on/off and volume only; Arcade sounds play only for Ken events with Ken's arcade mode on; no sounds while adoken is in the background, and during quiet hours only P0 sounds that delivery allows. Old `settings.toml` keys for removed options are ignored and no longer written.
- Today is redesigned around one honest summary (spec 0017, design `docs/design/today.md`, user decision 2026-10-01). A day-summary card gives a headline, one sentence and today's counts, with an illustration that follows the day's mood (shipped, finding your flow, helping things grow, waiting, blocked, clear, nothing moved yet, fresh start); a new picture decodes off the UI thread and crossfades in (swaps at once with Reduce Motion), and only the visible one stays in memory. The header shows the date, plus "Updated 12m ago · Refresh ⌘R" only when data is stale. Your PRs, most recently active first, show full titles, a segmented stage bar from Draft to Merged toned by what blocks it, up to three reviewer faces with vote badges, and what changed today ("2 commits today · 1 new comment", "Merged today at 14:32", "Conflict for 5h"). A side column holds Up next (the single most useful action, ↩ to act, `e` hides it until tomorrow), Waiting on you (one row per review, its age warming with time) and Loose ends ("Open 3d": days in the work item's current state); below 960 px everything folds into one column. `j`/`k` move within a column, `h`/`l` across, Home/End to the ends; `s`, `d`, `x` and `c` act on nudges as before, and every key is a ⌘P command. The day starts at local midnight and Today refreshes itself when its wording would change. Commit counts come from the iterations request adoken already sends, and "Open 3d" from a field sync already fetches, so Today adds no Azure DevOps requests.
- Notification settings moved from `notify.toml` into `settings.toml [notify]`, and saving them no longer replaces the whole file.
- Theme picker (user decision 2026-09-30): a clicked theme now sticks. Before, in the default "Match system" mode, clicking a theme whose appearance differed from macOS's only filled that light/dark slot; what you saw was the hover preview, and leaving the grid reverted it. Hovering no longer previews; a click or ↩ applies and saves, arrows only move the highlight. The All/Dark/Light filter, "Match system" (a light and a dark theme following macOS), ⌘P Match system / Always light / Always dark, and ⇧⌘L / app menu "Toggle Theme" are gone: you pick one theme, saved as `[appearance] theme`. Search "dark" or "light" to narrow the grid. Existing `mode` / `light_theme` / `dark_theme` settings open in the theme that was showing and are rewritten on your next pick.
- Pull requests show one pane at a time (spec 0004 §3.1, user decision 2026-09-30): the full-width list, or the full-width review, never side by side, so long titles are readable. ↩ or a click opens the review; Esc or the new "Pull requests" back button at the start of the review header goes up to the list with the same row selected and the scroll kept (⌘[ is now history back, see "Back and forward"). Opening a PR from ⌘P, the inbox or Today goes straight to its review. The list keys gained Home/End, PageUp/PageDown and ←/→ for the tabs (also ⌘P › "Pull requests: next/previous tab", "Back to pull request list"). The "Toggle pull request list" command is gone; ⌘⇧↩ now only toggles the full-width detail in Work items and Pipelines (⌘P › "Toggle full-width detail"). Rows show the full title on up to two lines, `!id · repository · author (avatar) · source → target`, the age, and badges: Draft / Active / Completed / Abandoned / Completing…, Merge conflict, Auto-complete, the number of active comment threads, CI status from the PR's latest pipeline runs, and reviewer avatars grouped by vote (approved, approved with suggestions, waiting for author, rejected; ringed in the vote's color), with required reviewers who haven't voted dimmed.
